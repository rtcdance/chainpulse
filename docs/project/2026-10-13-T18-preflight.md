## 3. 本轮发现的缺陷与修复

### 3.1 `--required-cases` 门禁**空转**（已修，F13/F21 同类）

**症状**：`verify-tests.py --required-cases test/acceptance/required-cases.json` 在 JSONL 全绿时**返回 0**，看似通过。

**根因**：`required-cases.json` 的 15 个场景（E01–E15）`tests` 数组**全为空占位符**；`verify()` 第 5 节按场景逐个检查其 `tests` 里的名字，空列表导致循环体从不执行 ⇒ **没有任何可失败的断言**。一个不能失败的门禁与"空 suite 假绿"（F13）是同一类缺陷。

**修复**（`scripts/acceptance/verify-tests.py`）：当 manifest **声明了场景但要求 0 个测试**时，显式失败：

```
✗ verification FAILED (1 issue(s)):
  - required-cases manifest requires 0 tests across 15 scenario(s):
    it is a placeholder, so this gate cannot fail
    (fill in the test names, or drop --required-cases)
```

并新增自测 `[PASS] self-test: placeholder required-cases manifest is a failure`。

**影响面**：CI 三个 workflow（`test.yml`/`coverage.yml`/`ci-integration.yml`）目前只用 `--jsonl ... --min-tests 1`，**未传 `--required-cases`**，故本修复不改变现有 CI 结果；它让该 flag 在真正被使用时不再假绿。

### 3.2 E01–E15 已**部分**映射到真实测试（8/15，已修）

原状：`required-cases.json` 的 15 个场景 `tests` **全空**（占位符）⇒ §7.2"必需场景都有实际执行的 Test"未满足。

**本轮把可本地执行的 lane 真跑了一遍**，并用真实通过的测试名填充：

| lane | 命令 | 结果 |

| unit | `go test -json -short ./pkg/... ./cmd/...` | pass=6803 fail=0 |
| contracts | `go test -json -tags=integration ./test/contracts/...` + `CHAINPULSE_RUN_POSTGRES_INTEGRATION=1`、`CHAINPULSE_TEST_DATABASE_URL=…:15433/chainpulse_t04`、`CHAINPULSE_RUN_REDIS_INTEGRATION=1` | **pass=23 fail=0 skip=0** |
| acceptance | `go test -json -tags=integration ./test/acceptance/...`（同上 env） | pass，除 Kafka 重投 1 例 skip |

> **关键点**：不带 `CHAINPULSE_TEST_DATABASE_URL` 时，contracts lane 的 **19 个 Postgres 测试全部 skip**（`requirePostgresIntegration` 门是"没设 env 就 skip"）。也就是说，**"contracts 全绿"在没配 DSN 时是"19 个真断言一个没跑"**。本文件用的是仓库里 T04 文档记录的 DSN（端口 **15433**，不是 5432）。

> **更正（重要）**：本文件早前一版写"E08 未实现：`pkg/` 里没有 429 / `Retry-After`"。**那是错的**，且错因值得记录：我用的是 `grep "429\|Retry-After\|RetryAfter"`，而 **BSD/macOS 的 `grep` 不支持 `\|` 交替**，于是它把整串当成一个字面量去搜，**必然搜不到**。实际实现存在于 `pkg/infrastructure/rpc/failover_client.go`（客户端 429 + `parseRetryAfter`，含秒数与 HTTP-date 两种格式）与 `pkg/plugins/api/rate_limiter.go`（服务端 429 + `Retry-After` 响应头）。⇒ **又一次"检查器本身也要被检查"**；后续同类检索改用工具级 `Grep`。

**验证**（三个 lane 的 JSONL 合并喂给检验器）：


即该门禁**不再是空转**：20 条必需断言真实执行且通过；删掉任一名字（或让其 skip）都会失败。
