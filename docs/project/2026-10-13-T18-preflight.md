## 3. 本轮发现的缺陷与修复

### 3.1 `--required-cases` 门禁**空转**（已修，F13/F21 同类）

**症状**：`verify-tests.py --required-cases test/acceptance/required-cases.json` 在 JSONL 全绿时**返回 0**，看似通过。

**根因**：`required-cases.json` 的 15 个场景（E01–E15）`tests` 数组**全为空占位符**；`verify()` 第 5 节按场景逐个检查其 `tests` 里的名字，空列表导致循环体从不执行 ⇒ **没有任何可失败的断言**。一个不能失败的门禁与"空 suite 假绿"（F13）是同一类缺陷。

**修复**（`scripts/acceptance/verify-tests.py`）：当 manifest **声明了场景但要求 0 个测试**时，显式失败：

```
✗ verification FAILED (1 issue(s)):
  - required-cases manifest requires 0 tests across 15 scenario(s):
    it is a placeholder, so this gate cannot fail
    (fill in the test names, or drop --required-cases)
```

并新增自测 `[PASS] self-test: placeholder required-cases manifest is a failure`。

**影响面**：CI 三个 workflow（`test.yml`/`coverage.yml`/`ci-integration.yml`）目前只用 `--jsonl ... --min-tests 1`，**未传 `--required-cases`**，故本修复不改变现有 CI 结果；它让该 flag 在真正被使用时不再假绿。

#### 6.1.1 冷 cache 复核（§7.3 明确要求"不以 warm cache 成功代替新 checkout 验证"）

第一次新检出构建用的是**共享的** `GOMODCACHE`（热的）——那样不能证明冷 cache 也能建。因此用空 `GOMODCACHE` 重跑：

**两条结论，其中一条**更正**了既有认知：**

### 8.1 覆盖率的 40% 门槛（§10「现有 40% 门槛用正确完整 profile 验证」）

命令与 CI 的 `unit` job **逐字相同**（`test.yml:114-115`）：

```bash
go clean -testcache
go test -json -short -coverprofile=coverage-unit.out -covermode=atomic \
  -timeout 120s -p 4 ./pkg/...
```

阈值计算也与 CI 逐字相同（`test.yml:212`）：

```bash
go tool cover -func=coverage.out | grep total | awk '{print $3}' | sed 's/%//'
```

**实测结果**：

| 项 | 值 |
| --- | --- |
| `go test` 退出码 | **0** |
| profile 大小 | 1,443,652 字节（非空、可解析） |
| **总覆盖率** | **70.4%** |
| `MIN_COVERAGE` | 40 |
| **裁决** | **PASS** |

### 9.1 场景与实测结果

| 步骤 | 动作 | A 摘要 | B 摘要 | A 事件数 |

### 11.3 §8 资源声明的**实测**：10 轮 start/stop 后 goroutine 归位

§8 原文要求"**10 轮 start/stop 后 goroutine 回到基线+20 以内**，并解释固定后台 worker"。本轮把这句话变成可执行断言：对**生产后台 worker `reorg.OutboxDrainerLoop`**（无外部依赖 ⇒ 泄漏可归因于 worker 本身而非连接池）做 10 轮 `Run`/`Stop`。

**实测**：`before=2 after=2 delta=0`（预算 20）⇒ **无泄漏**。工件写 `workers.goroutine.pprof` 与 `goroutine-report.json`；若超预算，测试会**逐个点名**残留 goroutine 的首帧（裸数字不可行动）。

**关键是那条正向控制**：每轮在 `Stop` 之前先自旋确认 ① 出现了一个新 goroutine ② `Run` **尚未返回**。没有这条，"无泄漏"可以在 **`Run` 立刻返回、worker 从未运行** 的情况下照样通过 —— 那正是本会话反复遇到的"假通过"形态。

### 11.4 🔴 自造缺陷：`commit_sha` 为空（已修）

首版 `bench-raw.json` 的 `commit_sha` **是空串**，而 `tree_dirty` 正常 —— 因为我写成了 `git_output("rev-parse HEAD")`：**两个词被当成一个参数**，git 于是去找一个名叫 `rev-parse HEAD` 的 revision，失败返回空；而 `git_output("status","--porcelain")` 恰好是两个正确参数，所以只有前者坏。
修法：`git_output("rev-parse", "HEAD")`。**这类"两个单词一个参数"的错误不会报错，只会静默产出空字段** —— 因为我在写入前断言了非空才没有流出去。
