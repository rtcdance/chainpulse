## 1. §8 的要求（原文）

> **微基准回归** | 同硬件/版本/语料下 ns/op、B/op 恶化超过 **15%** 阻断；有统计噪声时复测一次再判 | 至少 **5 次样本**，benchstat 与结构化数值；**no match、缺基线、无有效样本不能 pass**

T14 验收另加："性能劣化/**缺指标阳性对照使门禁失败**"。

最后那句是本工具存在的理由：**一个在"其实没比成"时还报绿的门禁，比没有门禁更糟** —— 它会让人以为测过了。所以下面三种情况在本工具里是 **FAILURE，不是 skip**。

## 2. 实现

`scripts/acceptance/bench-gate.py`（新，仅 Python 3 标准库）：

- **解析** `go test -bench` 输出（`ns/op` / `B/op` / `allocs/op`），按 benchmark 名分组；重复运行产生多份样本，这正是"≥5 次样本"的来源；
- **阈值 15%**，对 `ns/op` 与 `B/op` **分别**判定（严格大于才阻断 —— 恰好 +15% 不阻断）；
- **三种"不能 pass"**：
  1. **无有效样本**：某 benchmark 样本 < 5 ⇒ FAILURE 并报出样本数；
  2. **缺基线**：某 benchmark 在基线里没有条目 ⇒ FAILURE（新 benchmark 必须**显式**记录基线，不能默认继承通过）；
  3. **no match**：基线里有本次运行**没有产出**的 benchmark ⇒ FAILURE（两者不可比）；
- **空输出 / 空基线** ⇒ FAILURE（"跑出零个结果"不是通过）；
- `--write-baseline` **拒绝**记录样本不足的基线（否则会把噪声固化成门槛）；
- **`--self-test`**：10 个用例覆盖上述全部路径 + 阳性对照。

## 3. 验收

### 3.1 自测

```
$ python3 scripts/acceptance/bench-gate.py --self-test
bench-gate self-test passed (threshold 15%, min samples 5, 10 cases)
```

10 个用例：阈值内通过 / **ns/op 超 15% 阻断** / **B/op 超 15% 阻断** / 改善通过 / **样本不足阻断** / **缺基线阻断** / **基线多余条目阻断** / **空输出阻断** / **空基线阻断** / 恰好 +15% 不阻断。

### 3.2 真实数据端到端（非合成）

```bash
go test -run '^$' -bench BenchmarkDecodeEventDataTransfer -benchmem -count=5 ./pkg/evm/ > /tmp/bench_raw.txt
```

得到 5 份真实样本（`~1530–1561 ns/op`、`904 B/op`、`17 allocs/op`）。

| 步骤 | 结果 |
| --- | --- |
| 记录基线 | 1 个 benchmark，`ns_per_op 1539.6`、`bytes_per_op 904` |
| 同一份数据过门禁 | **PASS**（+0.0% / +0.0%） |
| 对**人为收紧**的基线（1000 ns/op、700 B/op） | **BLOCK**：`+54.0%` 与 `+29.1%`，逐条列出 |
| 基线含**不存在的 benchmark** | **BLOCK**：`baseline entries with no matching benchmark in this run: BenchmarkThatDoesNotExist` |

### 3.3 基线工件

`test/benchmarks/micro_baseline.json`（已入库）——含 **provenance**，明确标注：

> host 是 **macOS / Apple Silicon，不是 §8 的参考环境**（Linux 8 vCPU 16GiB SSD）。§8 要求 Mac 报告**单独标注、不得冒充参考环境数字**；本文件遵守该规则。门禁的作用是在**同一台机器**上抓回归 —— 15% 阈值正是针对这一点。
