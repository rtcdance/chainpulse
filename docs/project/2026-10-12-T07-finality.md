# T07 交付：finality

> 对应任务：`docs/specs/2026-10-12-web3-go-backend-delivery-plan.md` §5 的 **T07 / P0 / 6h**。
> 状态：**In Progress** —— bool 接口的降级语义与显式 confidence/source/observed_at 已完成并用真实 HTTP 桩验证；
> 调用方改造、provider 分歧检测、前端呈现 unknown/degraded 未做。
> 日期：2026-10-12，Asia/Singapore。

---

## 1. 缺陷（读码确认，两处独立）

`pkg/services/finality/finality_checker.go`：

**① `IsBlockFinalized`（bool 兼容接口）无视降级** —— 第 164 行：

```go
return result.IsFinalized, nil   // 即使 result.Degraded == true
```

而 `IsFinalized = blockNumber <= finalized`。`finalized` 在"标签不支持"时**已退到 `latest`**（第 122 行）⇒ **一个 latest 回退的高度会被当成 finalized 返回 `true`**，调用方据此**错误晋升事件**。

**② L2 的 `safe` 被当成 finalized** —— 第 99 行 L2 用 `tag = "safe"`，但 `degraded` **保持 false**（第 114 行只在 fallback 分支置 true）⇒ 从 `safe` 得到的答案被当作"有 finality 保证"。**违反 `safe ≠ finalized`。**

这正是 F08："用 L2 `safe` 近似 finalized、失败时退到 latest；bool 接口仍按高度返回真"。

---

## 2. 实现

### 2.1 显式 confidence / source / observed_at

新增两个枚举与三个字段：

| `FinalityConfidence` | 含义 |
| --- | --- |
| `unknown` | 无可用答案 |
| `degraded` | 来自 `latest` 回退 ⇒ **无 finality 保证** |
| `safe` | 来自 `safe` 标签 ⇒ **不是 finalized** |
| `finalized` | 来自 `finalized` 标签 ⇒ **唯一可晋升的来源** |

| `FinalitySource` | 取值 |
| --- | --- |
| `finalized_tag` / `safe_tag` / `latest_fallback` / `unknown` | 来源可追溯 |

`FinalityResult` 现含 `Confidence` / `Source` / `ObservedAt`（缓存写入时间，供调用方判断新鲜度）/ `FinalizedBlockNumber`（判决所依据的高度）。

### 2.2 判决规则

- `GetFinalizedBlockNumber`：按标签设置 `source`/`confidence`；**`safe` 与 `latest` 回退都置 `degraded = true`**，但用 `confidence` 区分二者。
- **`IsBlockFinalized`：仅当 `Confidence == finalized` 且未降级才返回 `true`**；否则返回 `false`（不再看高度）。
- `IsBlockFinalizedWithStatus`：把 `confidence`/`source`/`observed_at`/`finalized_block_number` 一并返回。

## 5. 调用方改造完成（2026-10-13，提交 `d0d8355`）

第 4 节第 1 条（"把 `IsBlockFinalized` 的所有调用方切到 `IsBlockFinalizedWithStatus` 并显式处理 unknown/degraded"）已完成。**但真正的病灶不在 `IsBlockFinalized`，而在生产写入路径上另一个函数**。

### 5.1 病灶：`GetFinalizedBlockNumber` 的高度被直接当成"已确认"的截断线

`pkg/plugins/api/block_confirmation_tracker.go` 的 `transitionPendingEvents` **只要拿到一个高度**就把它当作 `confirmed` 的截断线：

```go
finalizedBlock, err := fc.GetFinalizedBlockNumber(ctx, chainID)   // 只有高度
if err == nil && int64(finalizedBlock) > cutoffBlock {
    cutoffBlock = int64(finalizedBlock)                            // 直接采纳
}
... UPDATE events SET status='confirmed' WHERE block_number <= cutoffBlock
```

而 `GetFinalizedBlockNumber` **在降级时照样返回高度**：L2 走 `safe` 标签、标签不支持时退到 `latest`。于是 F08 不只是"报告层把 degraded 说成 finalized"，而是**写路径把事件晋升成 `confirmed`，而链并未承诺该高度**。

### 5.2 改动

| 位置 | 改动 |
| --- | --- |
| `pkg/services/finality/finality_checker.go` | `FinalityChecker` 接口新增 **`GetFinalizedBlockNumberWithStatus(ctx, chainID) (*FinalityResult, error)`**；`rpcFinalityChecker` 实现之；`IsBlockFinalizedWithStatus` 改为复用它（去掉重复的高度查询） |
| `pkg/plugins/api/block_confirmation_tracker.go` | 改用 status 版本；**`Degraded` 或 `Confidence != finalized` 一律退回深度确认**，并记录拒绝的是哪一档 confidence/source |
| 同上 | 抽出**纯函数 `confirmationCutoff(depthCutoff, status)`** —— 让规则成为一处命名、可直接测试的判定，而不是内联比较 |
| `GetFinalizedBlockNumber` | **保留**（只显示不晋升的调用方仍需它），但补注"高度本身不足以据此行动" |

`IsFinalized` 在高度查询的返回值里为 `true`：返回的高度**就是** final 高度，该高度的块按定义已 final。调用方真正要分支的是 **`Confidence`**（`Degraded` 是它的粗粒度版本）。

### 5.3 验收（全 PASS）

| 测试 | 断言 |
| --- | --- |
| `TestConfirmationCutoff`（7 例） | `finalized` ⇒ 抬高截断线；**`safe` / `latest_fallback` / `unknown` / "confidence=finalized 但 degraded=true" ⇒ 全部退回深度线**；无判决 ⇒ 深度线；final 高度低于深度线 ⇒ **不下调** |
| `TestBlockConfirmationTracker_AsksForConfidenceNotJustHeight` | 计数器**只由 status 版方法递增** ⇒ 若回退到 `GetFinalizedBlockNumber`，计数为 0，测试失败（钉住接线） |

| `TestBlockConfirmationTracker_ToleratesFinalityError` | finality 报错 ⇒ 退回深度确认，**不阻塞摄取** |
