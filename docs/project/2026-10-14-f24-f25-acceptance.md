## 1. F24：SIGTERM 优雅停机 + kill 崩溃

命令（`-tags=integration` + Postgres/Redis 门）：

```
go test -count=1 -tags=integration -run \
  'TestSigtermGracefulShutdown|TestCrashInsideCommitLeavesNothingBehind|TestCrashAfterCommitKeepsTheBlock' \
  ./test/acceptance/
```

| 测试 | 场景 | 结果 |
| --- | --- | --- |
| `TestCrashInsideCommitLeavesNothingBehind` | **kill 在提交过程中** → 不留半成品（含 `kill_00`…`kill_09` 共 10 个子用例，逐个 kill 点） | **PASS** (9.50s) |
| `TestCrashAfterCommitKeepsTheBlock` | **kill 在提交之后** → 已提交的块保留 | **PASS** (6.93s) |
| `TestSigtermGracefulShutdown` | **SIGTERM** → 优雅停机 | **PASS** (4.82s) |

⇒ 计划要求的"两类场景"（SIGTERM / kill 崩溃）**均实测通过**，且崩溃用例是**逐 kill 点**覆盖（10 个位置），不是只测一次。

## 4. ⚠️ 发现：`test/acceptance` **没有任何 CI lane 会跑**

核查：

```bash
$ grep -rn "test/acceptance" .github/workflows/
(empty)

$ grep -n "test-acceptance\|./test/acceptance" Makefile
(empty)
```

CI 跑的测试路径只有 `./test/integration/...`、`./test/contracts/...`、`./test/e2e/...`，**没有 `./test/acceptance/...`**；Makefile 也没有对应 target。

**影响**：

| 测试 | 所在位置 | 是否被 CI 跑 |
| --- | --- | --- |
| F25 三个 provider 受限测试 | `pkg/plugins/pullers/provider_limits_test.go` | ✅ **会**（属 unit lane 的 `./pkg/...`，且无 build tag） |
| **F24 三个停机/崩溃测试** | `test/acceptance/{sigterm,crash_kill}_test.go` | ❌ **不会** |
| `TestCanonicalDigestsAcrossRollbackAndRedelivery` | `test/acceptance/` | ❌ 不会 |
| E09 的 DB/Redis 故障测试（`TestDatabaseDisconnectIsBackpressure` 等） | `test/acceptance/` | ❌ 不会 |
| `TestKafkaRedeliveryKeepsEffectSingle` | `test/acceptance/` | ❌ 不会 |

也就是说：**计划 §9 的验收场景大量落在 `test/acceptance`，而这条目录在 CI 里是盲区**。我本会话手工跑的这些用例全绿，但**没有任何自动化在持续跑它们** —— 它们可以在不触发任何红灯的情况下腐坏。

这与计划 §10 另一条（"契约、Anvil端到端与依赖健康检查**不空跑**"）直接相关：`test/acceptance` 不是"空跑"，而是**根本不跑**。

**建议**（并入决策备忘录 D13）：给 `test/acceptance` 加一个 CI lane（需 Postgres/Redis 服务容器 + `-tags=integration`），或明确声明它只在手工/发布前运行。
