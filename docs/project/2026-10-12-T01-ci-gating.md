## 1. 本轮完成的内容

### 1.1 退出码传播（F01 / F10）—— 已修

问题：`test.yml` / `coverage.yml` 把 `go test` 的退出码存进变量后**从不使用**，每个测试步骤末尾 `exit 0`；timeout 只告警；coverage 缺失时 `touch` 占位文件后跳过阈值检查。结果：断言失败、超时、空跑都可能显示绿色。

修复（三个 workflow 一致）：

| 手段 | 说明 |
| --- | --- |
| `set -euo pipefail` | 管道中任一环节非零即失败，不再靠 `grep` 文本判断 |
| `go test -json ... \| tee x.jsonl` | 保留结构化证据（JSONL）供检验器消费 |
| `verify-tests.py --min-tests 1` | 空跑/无测试/`-run` 未匹配 → 失败 |
| 覆盖率文件缺失 | `exit 1`（不再 `touch` 空占位） |
| 覆盖率阈值不可解析 | `exit 1`（不再"跳过"） |
| 低于 `MIN_COVERAGE=40` | **失败**（不再只是 warning） |
| `if-no-files-found: error` | 必需工件缺失即失败，不创建空占位 |

改动文件：`.github/workflows/test.yml`、`.github/workflows/coverage.yml`、`.github/workflows/ci-integration.yml`。

### 1.2 `tests.jsonl` 检验器 + empty-run 检测（F21）—— 已实现

落点：`scripts/acceptance/verify-tests.py`（Python 3 标准库，零依赖，CI 可先行运行）。

统计口径（§7.2）：
- **test 动作** = 带 `Test` 字段的事件 → pass / fail / skip；
- **顶层 Test 名** = 不含 `/` 的 `Test` 值（**父子 subtest 的 pass 不计入**）；
- **package 成败** = 无 `Test` 字段的 pass/fail/skip 事件；
- **无测试包** = 从未发出 test 事件的包。

失败判据：断言失败、空跑（无 test 事件）、`--min-tests` 未达、必需包未跑、必需 case 未跑/被 skip、可选 unknown-skip。

自测：`python3 scripts/acceptance/verify-tests.py --self-test`（6 项全过）。

### 1.3 F13：第 7 个 workflow 的假绿 —— 已消除

`ci-integration.yml` 的 `contract` job 跑 `./test/contracts/...`，而该 suite **实测 0 个 Test**，`go test` 退出 0 → **PR 上必然假绿**。

处置：**保留真实测试、消除假绿**（选择"归并"而非"退役"，因为 `integration` job 有真实 147 个 Test，退役会丢覆盖）：
- 三个 job 全部接入检验器；`contract` job 因 suite 为空将**刻意变红**，直到 **T02** 补上 Postgres/Redis/Kafka 真实契约 runner 后转绿。
- 这不是"关掉检查"，而是让空 suite **如实失败**（计划原文："contract 空 suite 修复前禁止以 green 呈现"）。

**阳性对照实测**：`go test -json -tags=integration ./test/contracts/...` → `GO_EXIT=0`，检验器 → `VERIFY_EXIT=1`（`empty-run: no test-level events found`）。✅
